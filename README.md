# 健康平台 HTML 雛型

依 `V12-健康系統需求規格書.md`（草案 v0.6，2026-11-25）製作，用於確認需求與操作流程。

## 開啟方式
用 Edge 或 Chrome 直接開啟 `index.html`。不需要伺服器與網路。

- 右上角 **目前身分**：切換角色，選單與資料範圍會跟著改變。
- 右上角 **大字**：大字高對比（NFR-09）。
- 右上角 **重置資料**：清除操作紀錄。資料存在這台電腦的瀏覽器（localStorage）。
- 首頁「總覽」列出目前身分能用的模組、頁面與各情境的快速入口。
- **待辦摘要**（首頁）：依目前身分列出可處理事項的件數。
- **展示引導**：按展示情境的按鈕後，左下角逐步顯示下一步，可直接切到該步的身分與頁面。下一步需手動按，不會偵測是否完成；現場機台畫面不顯示。
- **意見回饋**（頁首右側）：記錄頁面、身分與意見，可匯出 CSV。只存在這台電腦的瀏覽器，不會傳送；「重置資料」不會清掉回饋。
- 首頁插畫可收合，瀏覽器會記住。
- 開會用的待確認事項、門檻審核欄與顏色試看紀錄在 `docs/確認表.html`（可直接列印）。

## 模組分類
上方分頁切換模組，左側欄只列出該模組的頁面；點模組名稱回到模組首頁。目前身分沒有權限的模組與頁面不顯示。

| 模組 | 分類與頁面 | 規格 |
|---|---|---|
| 健康管理 | 場景應用（模組首頁以卡片呈現）：職場／工地、高齡復健、機台模式、長照據點（延伸）、社區藥局（延伸）<br>量測與同意：同意管理、健康量測、健康量測列表、生活紀錄<br>分析與警示：個人趨勢、警示與處置、群體統計、管理儀表板 | 6.1～6.8 |
| 健康商品 | 我的衛教與購物：推薦、商品專區<br>商品與專業審核：商品主檔、推薦規則、諮詢回覆、不良反應與客訴<br>訂單與通路：訂單與批號、外部電商、銷售分析 | 6.9 |
| 知識助理 | 提問：作業知識助理、衛教問答<br>審核與文件：審核輔助、知識文件管理 | 6.10 |
| 系統設定 | 量測設定：指標主檔、門檻與版本、裝置管理、參考儀器配對<br>權限管理：功能權限總覽<br>稽核與部署：稽核紀錄、地端部署與待決事項 | 6.3、6.7、8 |

健康管理、健康商品、知識助理依規格書的模組劃分；「流程管理」（流程總覽）是雛型另外加的跨模組頁面，頁籤排在總覽右邊；「系統設定」是雛型另外分出的設定類頁面，不代表程式模組。分類清單集中在 `js/modules.js`，要搬動頁面只改該檔。

網站主題為健康自然風格（森林綠、米白、大地色）。各模組有自己的低彩度代表色，只用來表示目前所在模組；健康判定與狀態使用較鮮明的紅、黃、綠並附文字。版面已改為本雛型自有樣式，不再沿用現有系統（NiceAdmin）的版型。

## 雛型的限制
- 人名、數值、商品、許可字號、知識文件**全部虛構**。門檻「注意」級、WBGT 分級、量測模式秒數、各指標最短秒數、交互作用清單、禁用詞與紅旗詞都是示範值，**未經醫護、營養、職安或法務審核**。
- 量測、知識檢索（關鍵字比對，沒有語言模型）、金流、發票、電商同步都是模擬；不啟用攝影機。
- 權限與「伺服器端檢查」由瀏覽器程式模擬，**不代表任何安全保證**。正式系統必須在伺服器端實作。
- 不要輸入真實個資或健康資料。

## 建議展示流程
也可用首頁展示情境按鈕開啟逐步引導（重置資料後引導仍保留；修改下表步驟時，一併修改 `js/extras.js` 的 `GUIDE_STEPS`）。每個情境開始前先按右上角「重置資料」，避免前一個情境留下的警示或設定影響結果。

| 情境 | 步驟 |
|---|---|
| 同意控管 | 身分「許新進」→ 健康量測（無法開始，另試「略過畫面直接呼叫上傳 API」）→ 同意管理簽署 → 回量測 |
| 警示 | 身分「王示範」→ 模擬情況選「血壓偏高」量一次（要求複測）→ 再量一次（發出通知）→ 切「職安劉專員」→ 警示與處置 → 結案 |
| 品質與秒數 | 品質：身分「王示範」→ 模擬情況選「訊號品質不足」：不給數值、不產生警示<br>秒數：切「健康管理員阿德」→ 指標主檔啟用「呼吸頻率」→ 健康量測選受測者「王示範」、「快速」模式、「正常結果」：呼吸頻率顯示量測長度不足、不給數值（此指標為「實驗中」，只有健康管理員看得到） |
| 門檻版本 | 「健康管理員阿德」→ 門檻與版本 → 建立新版；舊紀錄的判定與引用版本不變 |
| 群體分布與小群組 | 「許主管」→ 群體統計：預設範圍顯示收縮壓分布圖；單位選「行政部」（少於 5 人）或「工程部」（與全部相減只剩 3 人）則不顯示 |
| 商品審核 | 「行銷阿宏」開啟 P005 看文案檢核 → P004 由「藥師方方」「法遵甲」依序審核 → 發布。可試系統管理者、資格到期的營養師（系統拒絕） |
| 推薦 | 「林長青」→ 推薦頁（指標未驗證，不推薦）→「健康管理員阿德」把收縮壓改「已驗證」→ 切回「林長青」的推薦頁（出現商品）<br>禁忌：勾「孕期或哺乳」並送出問卷，推薦停止；取消勾選並重新送出，商品重新出現<br>不適症狀：到「生活紀錄」開啟「我目前有身體不適」→ 回推薦頁，推薦停止 |
| 電商下架 | 外部電商串接勾「模擬同步失敗」→ 商品 P002 緊急下架 → 看告警與重試 |
| 自建購物 | 受測者下單 → 合法通知、重送、偽造簽章 → 行銷「訂單、出貨與批號」用批號查訂單 |
| 長照據點（延伸） | 「據點社工小安」→ 長照據點：關懷名單（魏玉蘭未報到、童添丁多次注意）→ 童添丁家屬未授權，通知被拒；開啟授權後通知（只有報到次數）→ 按「量測」帶入據點量測站 |
| 社區藥局（延伸） | 「林長青」→ 推薦頁的諮詢勾「附上最近一次量測」送出 →「藥師方方」→ 社區藥局看到分享的量測並回覆（資格到期的營養師看不到）→ 林長青撤回分享 → 藥師端顯示「本人已撤回」 |
| 知識助理 | 「職安劉專員」問作業助理；「王示範」用衛教問答試禁答與紅旗題；「法遵甲／乙」撤銷或核准文件後再問 |

## 製作時自行補上、需要確認的設計
規格沒有寫明，雛型先採以下做法：

1. 複測後數值恢復正常時，警示仍轉「待處理」並通知，由人員確認結案（FR-41 未定義這個情形）。
2. 群體分布依門檻分「低於／範圍內／高於」三類；任一類少於 5 人時，其他非零類別也不顯示。
3. 近期血氧「注意」級也會停止推薦（規格只寫「血氧異常」）。
4. 禁忌問卷有效期 180 天；個人基準線取最近 10 次同情境量測。
5. 職場情境（上工前、休息後、工地場域）的量測一律不用於推薦；規格另允許員工以個人身分加入，雛型未做加入流程。
6. 知識文件只做法遵一關（Q17 未定）。
7. 「發布」權限暫給商品與法遵角色（正式依 EIIS 設定）。
8. 現場機台的確認畫面 30 秒未開始量測就清除（FR-53 只要求結束後清畫面；30 秒為示範值）。結果畫面維持 15 秒。不論用什麼方式離開機台頁，都清除目前人員。識別畫面輸入後 30 秒未按確認，清空輸入內容。
9. 商品複審提前 30 天提醒（示範值）；逾期只提醒，不自動下架。
10. 電子郵件通知預設關閉，由健康管理員開啟，只影響之後的通知。
11. 量測同意由家屬代簽者，不開放個人化推薦。
12. 長照據點關懷提示：超過 3 天未報到、未結案警示、填報不適、近 3 次有 2 次以上「注意」（示範規則）。家屬通知需檢視授權，只含報到次數。
13. 社區藥局：本人在諮詢時勾選才分享最近一次非職場量測，可撤回；查看會記入稽核；資格到期者看不到。健康管理員可檢視此頁，但看不到分享內容、不能回覆。

「長照據點」「社區藥局」是依《應用場景與商業模式建議》新增的延伸場景，規格書 v0.6 沒有對應條文。
